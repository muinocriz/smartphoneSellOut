# 模块一「销量追踪」功能与长表迁移基线

依据 master 的 [3e9faf4](https://github.com/muinocriz/smartphoneSellOut/tree/3e9faf41a824976ffeb55a65427626f958e72d2f)。本文记录当前实现，并单列未来决策。目标是以 `sales-long.csv` 作为显示基础；`sales-estimates.csv` 是榜单估算历史，统计对象和用途不同。

## 一、目前显示的是什么

每条线代表数据表中的一个追踪对象，可能是单机，也可能是系列合计。单位为万台。默认打开自然周、累计销量、仅原始观测。精选样本不等于全市场排名；停更之后保留历史，空白不能解释为零销量、停售或退出市场。

| 环节 | 当前行为 | 对迁移的要求 |
| --- | --- | --- |
| 项目与本地导入 | 首页自动请求同目录 data.csv；失败显示原因和手动选文件入口。支持 UTF-8/BOM、GBK 回退、CSV 引号和千分位。brand、model、date 列必需，category 可选；缺品牌或机型的行略过，空白或非有限数字读为空。 | 保留本地替换数据源。按表头识别新旧格式；长表的非法 operator、重复记录、元数据冲突要指出行号，避免静默覆盖。 |
| 周历 | 从列名识别 ISO 周，支持 W34、2026W34 等，省略年份当前按 2026。以 UTC 周一排序并补齐最早至最晚间的所有周，拒绝无效周和重复周；跨年按 ISO 周年。 | 长表使用带年份的 period。先建立全局连续周历，再对齐各对象；两条相邻记录可能相隔数周。 |
| 身份与日期 | 选机、列表、颜色分配和临时编辑依赖原始品牌、机型与行顺序。日期读自该追踪对象的 date。 | 保留系列合计、品牌写法和稳定顺序。不要按机型表的 SKU 拆分系列，也不要在切换数据源时顺带替换开售日期。 |
| 空数据 | 有机型行而无观测、整周空列、个别机型断更是三种状态。自然周仍能显示空列。 | 稀疏长表只有观测行。若要保留全空机型或末尾空周，需要对象清单和周范围；不能用数值 0 占位。 |

## 二、选机与列表

- **首次打开**优先选「近12周新机」。截止周是整张表最近一个有值的周，向前含当周共 12 个 ISO 周。机型须有观测，且所填日期落入窗口。仅新增一个空周不会移动截止周。名单为空时回退为当前品牌中有数据的全部机型。
- **切换品牌**时，单品牌默认选中有数据的全部机型。点击品牌「全部」则每品牌选一款：先比谁有更新的相邻精确累计差分周，再比该周增量。旁边的「全选」才会选中当前范围内所有有数据机型。支持单独勾选和清空。
- **本周／跨期里程碑**以每个品牌自己的最新有值周为准。取当前累计达到的最高整 50 万档，与该机型此前历史最高档比较，避免下降后回升时重复入选。上一自然周有精确观测归本周；跨缺口、上一点为下限、首次只有下限记录归跨期。首次只有精确累计且没有此前观测，不认定当周跨档。名单按门槛降序。跨期仅能确认达到的区间，模型估计的达成周另标。
- **自建列表**支持保存当前选择、命名、修改名单、二次点击确认删除、JSON 导入与导出。列表存在 localStorage，保存的是 `brand|model`；套用时跳过数据源里不存在的对象。动态系统列表实时计算，可另存为快照。改名、品牌归并、换 ID 都可能使旧列表失配。

## 三、时间轴、差分和估算

| 功能 | 实际规则 |
| --- | --- |
| 自然周与完整销售周 | 自然周显示 ISO 周和周一起始日期。生命周期轴对每款机型单独平移，周一开售则当周 W1，其余以下一周一为 W1。有效日期之前及不完整周不进入 W1 起的折线；日期缺失或无效仍可看自然周。 |
| P0 | 非周一开售时，从开售日到周日含首尾，周五为 3 天，周日为 1 天。生命周期表单列 P0 天数和该周末的原始累计，切到周增量时此格仍为累计。周一开售显示不适用。P0 末和 W1 末都有精确累计时可以差分出 W1。 |
| 周环比增量 | 当前只从相邻自然周的累计做减法，再投影到所选横轴；显示单位为万台。首个有值周没有前周观测时留空。相邻精确累计倒挂可产生负值并提示异常；对数图隐藏非正值，明细表仍保留。 |
| 仅原始观测 | 默认模式。缺失断线。现行宽表没有 operator，代码把每个正的整 50 万倍数推断为虚拟下限（含临时编辑值）。显示空心菱形和 ≥，与这类点相邻的差分不算真实周增量。数值 0 不触发该规则。 |
| 线性插值 | 仅在两侧有记录、左端非负且累计未下降时分配区间差额。按经过的自然周数均分，首尾之外不外推。累计内点和受影响的周增量标 ≈；右端即使为精确累计，止于它的周增量仍可能是估算。 |
| 历史趋势约束 | 可选断更前 3／4／6／8 个连续真实增量，默认 6。倒挂、虚拟或缺失端点会中断取样；至少 3 个正增量才拟合对数增量趋势，拟合度低于 0.2 回退线性。相邻预测增量比限制在 0.8–1.25，最后按权重归一到端点差额。 |
| 下限端点 | 左端、右端或两端都可以是下限，甚至可相邻。用记录数值之差作参考情景；左端为下限时，这个差额也不能称作真实增量下限。估算与虚拟点不进入真实差分选机。 |

生命周期文档中的 W4/W8 健康度、分级及自动对标属于设计草案；当前首页没有这些操作入口。

## 四、图表、表格与图片

| 功能 | 用户能看到或操作的内容 |
| --- | --- |
| 图表与范围 | 累计／周增量、自然周／完整销售周独立切换。起止下拉框、「全部」和滑块同步。桌面支持拖动平移；触屏通过滑块或下拉框调范围，保留页面纵向滚动。切换纵轴指标保留当前窗口，切换横轴重设范围。 |
| 标识与主题 | 品牌色系、同品牌色差和按需补品牌名；普通观测实线，参考估算虚线和空心点，里程碑空心菱形。可开关数值标签和对数轴，悬停显示单位、符号及估算说明。桌面线尾名称避让，悬停高亮。支持浅／深色，手动选择保存在本浏览器。 |
| 手机网页 | 宽度 ≤600px 切为线尾编号与可滚动列表，默认关闭数值标签，可点列表高亮。按各机型在**当前窗口内最后一个可见值**降序，不要求这些值属于同一周；含下限时按标示数值排序。图例最多四位有效数字，不补尾零。 |
| 明细表与提示 | 所选机型逐行，日期及周值倒序，最近周在左。显示当前横轴的全部列，图表缩放不会裁剪表格。数值一般显示两位小数；缺失为破折号，估算／下限带符号。另提示倒挂、缺数据、日期不适用、估算区间及里程碑。 |
| PNG 导出 | 两端仅导出所选窗口内有值的曲线，沿用指标、主题、估算标记。桌面基础尺寸 2400×1350；模块一手机图为 **1200×1500（4:5）**。手机导出省略普通点值标签，列表超过 4 项排双列，最多两列各 6 行，超额留一格提示其余数量。文件名含列表／品牌、横轴、指标、估算模式及终端。 |
| 免责附注 | 桌面和手机都支持换行、恢复默认、清空不占位；有文字按需增加图片高度。常规文案存在 localStorage。有临时值或新增周时默认追加“含本标签页临时数据，仅供参考”，可独立编辑；重置临时数据后恢复常规文案。 |

## 五、临时编辑与模块四的接口

1. 累计模式下可双击或用 Enter 编辑单元格，包括原来缺值的周。输入非负有限数值，与前后记录倒挂时可确认继续。Enter 或离焦保存，Esc 取消；清空输入或点回退恢复原值。周增量和自动插值本身不作为编辑原值。
2. 可逐周追加，最多临时新增 52 周；支持全部重置。修改后图、表、默认选机依据、里程碑和导出数据重新计算。临时覆盖用品牌、机型、ISO 周一定位，存在 sessionStorage。同标签页刷新后可恢复，正式原值变化会使对应旧覆盖失效。
3. 导出的是完整 `data.csv`，包括未勾选机型、原列名及顺序、额外字段；追加新周或已编辑的隐式缺周。仅回填手动修改，插值不写回。新增空周本身也是可导出的状态。导出文件使用 UTF-8 BOM。
4. 同源嵌入的模块四通过 `window.parent.getTrackingUpdatedCSV()` 和 `tracking-data-change` 读取临时数据。有临时修改时返回完整宽表，否则返回 null。把首页的输入改为长表，并不会自动升级这个接口。若改返回格式，应同步修改模块四；若继续返回宽表，应定义特殊记录如何处理，避免丢失运算符。

## 六、两份正式数据的实际差异

基线为 2026-W34 至 W46。按“品牌＋机型＋ISO 周＋累计指标”对齐，两表均有 55 个追踪对象；484 个共有记录数值一致。长表共 485 行观测，含 484 条精确累计、1 条下限累计，尚无 weekly 记录。下列成因由维护者确认。

| W46 追踪对象 | data.csv（万台） | sales-long.csv（万台） | 原因 |
| --- | ---: | ---: | --- |
| REDMI K100 | 13.64 | 空 | 长表尚未更新 |
| REDMI K100 Pro | 54.17 | 空 | 同上 |
| REDMI K100 Pro Max | 62.4 | 空 | 同上 |
| REDMI K90 至尊版 | 61.55 | 空 | 同上 |
| REDMI Turbo 5系列 | 258.26 | 空 | 同上 |
| 华为 Mate 80系列 | 空 | ≥1000 | 原始数据表无法记录带运算符的估计值，故有意留空。长表明确记录下限。 |

前五条应按正常数据更新流程同步；最后一条应保留为长表独有的有效信息。不能用一张表批量覆盖另一张，也不能把 Mate 80 的 1000 当作精确累计去差分。

## 七、建议的迁移边界与待定口径

**先换读取层，保留现有图表入口。** 当前首页多个功能直接读取同一组累计数组。长表应先按对象和 ISO 周组织原始记录，保留 metric、operator、value_wan，再分别提供累计值、周增量、显示符号和来源。图、表、选机、里程碑与 PNG 应共用这些判断。仅把长表透视为数字矩阵会在第一步丢掉迁移所需的信息。

| 长表记录 | 建议的显示及计算规则（待实施） |
| --- | --- |
| cumulative，= | 精确累计。即使值为 50、100、1000 也照常作为精确值；“跨过整 50 万档”仍可触发里程碑列表，与观测精度独立。仅旧宽表导入保留旧推断。 |
| cumulative，>= | 显示 ≥，可确认至少达到相应门槛；沿用下限端点参考情景，排除真实差分。 |
| cumulative，< 或 ≈ | 原样显示上界或约数。两种记录都不能证明达到所写门槛。首版建议不作为插值锚点或真实选机依据。保留“来源提供的约数”和“页面计算的插值”两种来源说明。 |
| weekly，= | 是可直接读取的周观测。建议优先展示直接观测，再用相邻精确累计差分补缺；两者并存且不一致时保留两份来源并提示差异。是否计入每品牌选机、拟合样本，需明确后启用。 |
| weekly，<、>= 或 ≈ | 可在对应周展示符号，不作为精确增量，不自动倒推累计。有 weekly 而没有 cumulative 的机型，应能在周增量视图选中，在累计视图显示缺口。 |
| 没有记录／数值为 0 | 分别表示缺失／有记录的零。没有绝对累计基准时，一串 weekly 无法确定累计起点；也不能从两个不相邻累计直接得出末周销量。 |

**切换前需确定三件事。** 第一，直接周增量与累计差分不一致时，图表、手机排序和品牌选机是否一律采用同一优先级。第二，临时编辑是否支持修改运算符和 weekly；缓存至少应区分来源、指标、运算符与原值，避免“≥1000 改为 =1000”仍套用旧草稿。第三，完整下载和模块四交接是继续兼容宽表，还是提供可无损保留两种指标及运算符的长表出口；空周和全空机型另有表示需求。

**未来人工验收场景。** 用 W46 五条同步后的 REDMI 数据核对原图和周差分，用 Mate 80 验证下限、跨期里程碑和导出符号；另覆盖精确整 50、零、上界、约数、仅有 weekly、跨年 W53、内部缺周及上市 P0。最后用同一组选择对照桌面图、手机图例、两种 PNG、临时值刷新和模块四导入。此处是未来验收清单。
