# 机型销量生命周期分析与自动对标规范（设计草案 v0.1）

> 状态：完整周横轴、P0表格展示、ISO周共享计算模块已在旧版销量追踪模块实施；W4/W8评级与自动对标流水线尚未实现；适用项目：smartphoneSellOut / 销量追踪模块。  
> 目标：为后续 CSV → 周销量 → 生命周期指标 → 自动对标 → 内容导出的流水线提供**可复现、可测试、可版本化**的规则。  
> 旧版销量追踪模块现有“完整销售第N周”视图与未来W4/W8分析**统一使用同一套完整ISO周编号**。原有“发布后第N周”以部分上市周为第1周的规则已废弃。

## 1. 统计对象与边界

- 根目录 `data.csv` 每行是一条品牌＋机型记录，`brand,model,category,date` 等为主数据，`2026W34` 一类字段为 **ISO 自然周截止累计销量**，单位**万台**，**不是周销量**。
- 数据是**精选机型样本**，不是全市场 TOP 榜；机型从样本退出、未采集、缺列均不代表销量归零。
- `date` 是仓库现有的**发布日期**字段；只有经过确认它等于“实际开售日期”时，才能据此计算有效销售天数及生命周期。若两者不同，未来应引入 `sale_start_date`，并使用后者；缺少可信开售日期时标记 `SALE_DATE_UNVERIFIED`，不做严格生命周期评级。
- 本规范的健康度是**样本内周销量保持能力**，不是官方销售排名、需求强弱、市场份额、盈利情况或销量规模评级。

## 2. 两套时间轴必须并存

1. **日历周口径（ISO calendar week）**：周一到周日，跨年时使用 ISO 周年，不可简单用日历年；列名统一为 `GGGGWww`（例如 `2026W45`），与 `date.isocalendar()` 一致。用于同一时间窗口的市场竞争和现有图表。
2. **生命周期完整周口径（W1...W8）**：以开售后**首个真实完整7天ISO自然周**为 W1，每周连续编号；用于 W4/W8 指标、代际对比、同类机型健康度。
3. **P0 部分首周**：若周二至周日开售，开售所在的 ISO 周为 P0（1—6天），下一 ISO 周才是 W1。若周一开售，开售周即 W1，**没有 P0**。
4. **统一旧版销量追踪模块与未来计算口径**：`index.html` 的“完整销售第N周”按相同W1定义生成横轴，图表、数据表、导出和后续指标均共享该映射；旧的“发布日期所在周=第1周”规则不再使用。日期逻辑已抽取至仓库根目录 `iso-sales-week.js`，网页通过全局 `IsoSalesWeek`、未来Node流水线通过 `require("./iso-sales-week.js")` 调用。为避免歧义，保留ISO日历周视图单独用于同期观察。

### 周次计算算法

- `sale_start = sale_start_date ?? verified(date)`，按同一统计市场本地日期解释，不进行 UTC 日期偏移。
- `iso_monday(d) = d - timedelta(days=d.weekday())`（周一为0）。
- 若 `sale_start.weekday() == 0`：`w1_start = iso_monday(sale_start)`；否则 `w1_start = iso_monday(sale_start) + 7 days`。
- `week_k_start = w1_start + 7*(k-1) days`，`week_k_end = week_k_start + 6 days`，`k>=1`。
- 如果有 P0：`p0_days = 7 - sale_start.weekday()`；否则 `p0_days = 0`（不生成 P0）。不能将“满4天”称为完整周，也**不以不足7天的P0作为正式指标分母**。
- 截止数据覆盖到某个 ISO 周 `last_complete_iso_week` 时，只有 `week_k_end <= last_complete_iso_week_end` 才算时间上完成观察期；时间完成 **不代表**数据完整。

### 旧版销量追踪模块 P0 表格展示

- 完整销售周表格在机型及发布日期后增加 `P0天数`、`P0末累计` 两列，不改变W1...W8图表及保持率分母。
- `P0末累计` 是P0所在ISO自然周**周末累计销量**，并非P0单周销量（CSV缺少相邻周基数时无法计算后者）。无论页面当前选择累计销量还是周增量，列标题始终明确写作“末累计”。
- 周一开售没有P0，显示“不适用”；有P0但该周累计值缺失则显示`—`；P0销量不线性折算。
- 手动核对周一/周三/周日、跨 ISO 年与非法日期等日期边界。

### 日期示例

2026-09-09（周三）开售：2026W37=P0（5天），2026W38=W1，2026W41=W4，2026W44=W7，2026W45=W8。周一开售机型：开售周即W1，W4和W8分别是之后第3和第7个ISO周。

## 3. 从累计销量到真实周销量

给定机型在 ISO 周 `t` 结束时的累计销量 `C[t]`，周销量：

`S[t] = C[t] - C[t-1]`

其中 `t-1` 必须是**紧邻的上一个 ISO 周**（包括跨年），且两者口径一致、数值有效。P0、W1、W4、W8的销量都由对应自然周的 `S[t]` 得到。

- 不允许用“第一个非空累计值”充当周销量；不能跨缺失周直接差分后当成单周销量。
- 缺失值、尚未上市、样本退出均记为 `null`，**不能填0**。如果累计值有效且与前周完全相同，允许真实周销量为0，但比率分母为0时指标为 `null`。
- 若 `C[t]<C[t-1]`，标记 `NEGATIVE_DELTA` 并暂停该周指标，待核查是否为修订/口径变化。
- 对数据行重复、ISO周列错误、口径改变、单位变化等给出数据质量标记；保留原始值和来源，不静默修正。
- 如果没有可信的销售日实际值，即使知道 P0 天数，也不能凭累计销量**推测**P0日均销售趋势。P0 可展示实际周销量及 `p0_days`，不进入主评级。
- 若 `date` 为发布日而非开售日、或上市周累计数含预售/其他产品数据，应在数据处理阶段显式标记。

## 4. 核心指标与缺失处理

以下均指**完整7天**的周销量，单位万台，比例值按百分比存储或展示并注明单位。

| 字段建议 | 定义 | 解释 |
| --- | --- | --- |
| `retention_w4_pct` | `100 * W4 / W1` | 初期周销量保持率 |
| `retention_w8_pct` | `100 * W8 / W1` | 中期周销量保持率 |
| `late_retention_pct` | `100 * W8 / W4` | 从W4至W8的后期保持率（**不是数学斜率**） |
| `smoothed_retention_pct` | `100 * (W6+W7+W8) / (W3+W4+W5)` | 相邻3周平滑走势；要求全部6周可算 |
| `sales_w1_to_w8` | `sum(W1...W8)` | 8个完整周销量合计；不得把缺失周当0 |
| `sales_p0_to_w8` | `P0 + sum(W1...W8)` | 只有P0确实存在且完整可计算时输出；周一开售无P0时等于 `sales_w1_to_w8` |

如任一必需周销量缺失，相关指标置 `null` 并给出原因；分母为零时比值置 `null`，不显示无穷大。指数超过100%意味着该观察周销量高于基准周，**不应自动推断缺货结束、需求增长或销售成功**。

### 观察期与数据状态

- 未完成W4：`OBSERVING`，仅显示已有销量。
- 已完成W4、尚未完成W8，且W1/W4可算：`W4_PRELIMINARY`，仅输出初评指标。
- 已完成W8且W1、W4、W8以及规则所需各周数据有效：`W8_ELIGIBLE`，可输出正式的**试行等级**。
- 时间达到但关键数据不全：`INSUFFICIENT_DATA`，不得评级，需标记具体缺失周与原因。
- 当前过渡阶段如用W7替代W8：结果字段必须叫 `retention_w7_pct`、状态叫 `W7_TRIAL`；**不能沿用W8阈值冒充正式等级**。保留配置 `evaluation_horizon: 7|8`，默认正式版为8。

## 5. 分级：试行而非行业标准

先以**双维度**呈现：①周销量保持能力（S/A/B/C/D）；②后期走势类型；另外独立展示绝对销量。**所有阈值均为栏目自建待校准值，不是业界通用标准。**

### 5.1 W4、W8联合等级（仅 W8 观察期）

必须同时达到每级的两个门槛，按 S→A→B→C 顺序尝试，均不满足为D：

| 等级 | W4/W1 | W8/W1 | 含义 |
| --- | ---: | ---: | --- |
| S | >=60% | >=40% | 保持能力优秀 |
| A | >=45% | >=30% | 保持能力良好 |
| B | >=30% | >=20% | 保持能力一般 |
| C | >=15% | >=10% | 保持能力偏弱 |
| D | 未达C双门槛 | 未达C双门槛 | 保持能力很弱 |

例：W4=70%、W8=25%，两门槛同时满足的最高等级是B。等级表达的是**相对保持程度**，并非“爆款”“销量高”或全市场成功。

### 5.2 后期走势类型（仅在 W4 > 0 且 W8 有效时）

| W8/W4 | 标签 |
| --- | --- |
| >=120% | 持续放量型（仅代表端点比较） |
| >=85% 且 <120% | 稳定销售型 |
| >=50% 且 <85% | 正常回落型 |
| <50% | 快速衰减型 |

**禁止**仅凭这两个端点下定论：实际解读必须参考W5—W8走势，促销、缺货、集中交付等需要注释。销量保持评级与走势类型分开报告，如 `B级·持续放量型`。

### 5.3 数据不足时

不得给 S—D、不得以“D级”代替缺失。W7试算可发布纯指标及趋势描述，正式W8等级不得移植至W7；未来若需W7等级，须另设经历史样本校准的阈值及版本。

## 6. 自动对标：为后续流水线预留

数据量增大后自动建立四类**独立**对标关系，不把它们混成同一个排行：

| 对标池 | 硬约束 | 优先排序/人工配置 |
| --- | --- | --- |
| 同期竞品 | 同统计市场、形态/定位可比、同观察期有效 | 上市日期差优先<=30天，价格接近 |
| 上一代 | 同产品线、明确的 `predecessor_id` | 不依赖模糊名称猜测，人工初次核准 |
| 同品牌 | 同品牌、相近定位、同期可观测 | 同ISO周竞争与同生命周期表现分开 |
| 同级标杆 | 同市场/形态/价位段、足够历史样本 | 中位数/分位数；样本量不足则不产出排名 |

**比较时间轴**：同期市场竞争比较相同ISO周的实际周销量；代际/生命周期比较相同Wk；不得将2026自然周W44与上一代的其他生命周期周直接相比。

未来机型主数据应补充：`model_id`、`brand`、`series_id`、`generation`、`predecessor_id`、`form_factor`、`price_launch`、`market`、`sale_start_date`、`data_source`。当前CSV仍可保持不变，建议使用独立 `model_metadata.csv` / JSON 逐步补足；名称只作显示，ID用于关联。

建立一次固定对标池（新机入库时冻结）以及每周可更新的动态池；允许显式的强制包含/排除覆盖规则，变更留审计记录。

## 7. 自动化流水线目标与输出契约

建议顺序：

1. **Ingest**：读取 `data.csv`，检查编码、CSV头、重复机型、单位、日期和ISO周列；只读取，不修改原CSV。
2. **Normalize**：转换为长表 `model_id, iso_year, iso_week, cumulative_sales, source...`；规范跨年周排序。
3. **Delta**：仅相邻两周都有累计量时计算 `weekly_sales`；输出异常和数据覆盖说明。
4. **Lifecycle**：直接复用 `iso-sales-week.js` 生成P0/Wk映射及完整周状态；与旧版销量追踪模块“完整销售第N周”保持相同的Wk编号，不另起一套规则。
5. **Metrics**：计算W4/W8/平滑指标、可用性和分级；配置文件锁定规则版本（`methodology_version`、`evaluation_horizon`、`threshold_version`）。
6. **Benchmark**：生成固定/动态四种对标池；保留匹配理由、拒绝原因与同组样本量。
7. **Export**：导出适合审查的CSV/JSON和图文素材；**不要默认写回原始 `data.csv`**。
8. **Validate/Review**：单元测试与人工审核后再发布对外健康度结论；可由GitHub Actions编排，尚未在本次文档提交中部署任何定时执行。

推荐最少输出：
- `weekly_sales.csv`：`model_id,iso_week,weekly_sales,quality_flags`
- `lifecycle_metrics.csv`：`model_id,w1_iso_week,w4_iso_week,w8_iso_week,w1_sales,w4_sales,w8_sales,retention_w4_pct,retention_w8_pct,late_retention_pct,grade,trend_type,eligibility_reason,methodology_version`
- `benchmark_matches.csv`：`target_id,peer_id,relation_type,match_score_or_reason,selection_version`
- `quality_report.json`：缺失、异常差分、未核实开售日期、覆盖不足、样本退出等；明确统计基准和导出日期。

## 8. 验收测试清单（未来实现须通过）

1. 周一开售 → 当周W1，无P0；周二至周日开售 → 部分周P0，下一周W1；周日P0=1天。
2. 2026-09-09开售 → P0=2026W37(5天)，W1=2026W38，W4=2026W41，W8=2026W45。
3. 跨ISO年（例如2027年元旦附近）→ 使用ISO周所属年，不因 `calendar year` 与 `ISO year` 不同而错位。
4. 相邻累计值20→25 → 周销量5；20→空→25 → 中间和后一周都不得被误算为单周5。
5. 缺失与0区分；负差分报警；W1=0时保持率为null。
6. 时间满8周但W8缺失 → `INSUFFICIENT_DATA`，不得正式评级。
7. W4/W1=70%、W8/W1=25% → B级（双门槛）；W8/W4=90% → 稳定销售型。
8. W7试算不得使用W8正式评级名称或阈值。
9. 新旧代必须按相同生命周期Wk比较；同期竞品必须按相同ISO周比较。
10. 新功能不得改变原始CSV、自然周累计销量/增量数据或静态Pages部署；旧版销量追踪模块生命周期横轴与分析流水线统一按首个完整ISO周为W1，须同步校验图表和表格。

## 9. 版本治理与待确认事项

- 本文件是 **v0.1设计草案**。建议实施时先做数据完整性报告，再做核心指标，再做自动对标，最后做定时流水线与公众号素材输出。
- 需要明确 `date` 是否开售日、每周累计值是否始终为周日截止、是否存在系列合并口径、前代机型的主键关系；未确认之前对应结果必须展示口径警告。
- S—D阈值、后期走势阈值均是**可配置试行门槛**。积累足够同类历史机型后按产品形态/档位校准，版本改变应能复算旧报告。
- 对外文案应显示“精选样本”“累计销量差分”“数据截止周”“已完成观察周数”“数据不足原因”，不把未采集机型解释为销量为0。

旧版销量追踪模块完整销售周横轴、P0表格展示和共享日期模块已提交；本文其他指标、评级、自动对标及自动化流水线仍是待实现的设计契约。
