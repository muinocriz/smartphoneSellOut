本文保存项目的**长期规则**，面向更新数据、调整界面和维护导出逻辑的贡献者。用户首次访问请先阅读 [README](../README.md)，历史更新见 [CHANGELOG](../CHANGELOG.md)。

| 模块 | 页面 | 数据来源 / 编辑位置 | 导出 |
| --- | --- | --- | --- |

## 2. 销量追踪 CSV 规范

`data.csv` 每行对应一条品牌＋机型记录；周列是**累计销量（万台）**，周销量通过相邻周的累计值差分得到。

```csv
brand,model,category,date,2026W34,2026W35
华为,Pura 90系列,旗舰SO,2026/5/9,128.82,134.06
```

| 字段 | 要求 |
| --- | --- |
| `brand` | 品牌，必填 |
| `model` | 机型，必填；同品牌下名称不可重复；通常不重复写品牌前缀 |
| `category` | 分类，可留空；用于悬停提示 |
| `date` | 中国大陆正式开售日期；无法查证时暂用正式发布日期；支持 `2026/5/9`、`2026-05-09` |
| `2026W34` 等 | 周列，推荐携带年份；`W34` 不带年份时由 `index.html` 的 `DEFAULT_YEAR` 解释 |

维护注意：

- 新周数据在末尾追加周列，缺失单元格留空，**不要填零**；默认原始观测显示断线而非销量归零；可在研究视图选择有限端点间的估算，禁止回写事实表。
- CSV 可使用 UTF-8 或 GBK，编辑前注意检查日期、单位与累计序列是否递减。
- 「我的列表」用品牌＋机型标识条目；更改 `model` 会让旧列表的引用失效，需要重新选择并更新列表。
- 页面中称为「累计销量」而非「原始值」或直接「周销量」；周增量须与累计值区分。
- 样本非全市场 TOP 榜，可能不含老款苹果、低端走量机型或定制机。旧机型退出采样不是停销，缺失也不是零销量。

### 每周更新流程

1. 从已授权公开来源核对周期与数据口径，更新 `data.csv`。
2. 检查新增列名、数量级、缺失值、累计销量异常下降。
3. 本地预览销量折线和数据表，确认品牌筛选、里程碑与手机布局正常。
4. 提交 `data.csv`；Pages 自动发布静态内容，无需每周修改 `index.html`。

公开来源主要包括微博的 **RD观测**、**数码闲聊站**；请尊重原始发布者版权并明确注明整理／估算性质。

### 完整 ISO 周生命周期（已实现）与自动对标（规划中）

完整销售周横轴和 P0 表格已上线；新机健康度 W4/W8 销量保持率、自动对标池及自动化流水线仍处于规划阶段。方法和输入输出规范参见 [《机型销量生命周期分析与自动对标规范》](SALES_LIFECYCLE_SPEC.md)。

**统一周次口径**：模块1的“完整销售第N周”和未来健康度模型均以从所填日期起的**首个完整7天ISO自然周**为W1；不足7天的上市当周称为P0，不进入完整销售周W1—W8序列，但在数据表单列展示P0天数和P0所在周末累计销量。周一上市则该周为W1。现有 `date` 字段统一按正式开售日期维护（模块1历史界面仍可能显示“发布日期”）；无法核实正式开售日时采用正式发布日期作为暂定开售日。生命周期计算沿用现有字段，不新增日期字段。健康度自动化流水线尚未上线。

## 3. 销量追踪的交互与设计原则

以下为长期约定，调整图表时应避免无意破坏：

- **线尾标名、不使用图例**：桌面端直接在线尾显示机型；手机端使用序号与图下列表，减小横轴占用。
- **机型名称规则**：只展示同一品牌时可省略品牌；跨品牌时带品牌。以数字开头或名称不超过 3 字符（如 `15`、`600系列`、`Win`、`K90`）的机型保留品牌前缀，避免歧义。移动端溢出时优先删品牌、再截断；跨品牌选择按钮仍显示品牌。
- **默认跨品牌选择**：「全部」中每品牌取最近已更新周的最大周增量机型；优先数据更新到更近一周的记录。
- **自然周与完整销售第 N 周**：两种横轴；从所填日期起首个完整7天ISO周为W1，若所填日期是周二至周日则当周为P0并在此视图排除；周一则当周W1。未填日期的机型不显示在完整销售周视图，应提供提示。
- **两种数值模式**：累计销量与周增量；量级差大时允许使用对数轴。
- **数据表**：最新周在最左，横轴图仍按时间从早到晚。完整销售周视图中最大的 N 在左；机型和发布日期后增加 `P0天数`、`P0末累计` 两列。P0末累计是上市当周周末**累计销量（万台）**，不是P0周销量，即使切换周增量模式也保留清楚标注。周一上市P0为“不适用”；上市周历史数据缺失则P0末累计为 `—`，不能补0或推算。
- **值标签**：图中最多两位小数，手机列表取整。超过 12 条线时不画数据点，避免拥挤；重叠标签可以隐藏。
- **滚轮与触屏手势**：鼠标滚轮和触控板滚动不缩放图表；不在图表上启用拖动或双指缩放，保证页面自然滚动；改用范围滑块与选择框。
- **本周/跨期里程碑**：按各品牌最新有效记录周、此前最近记录和历史最高已确认累计下限判断，达到（≥）新的50万台整数倍；相邻周为本周，间隔多周为跨期，仅确认最新观测已达门槛；首次观测无前点、重复已达门槛不触发。不使用估算触发，估算模式可提示推测达成周。
- **我的列表**：新增系统动态列表「近12周新机」：以CSV中**全样本最后一个有累计销量值的ISO周**为截止，自动选择该周及之前11个ISO自然周内按 `date` 上市、且有累计销量记录的机型（`date` 按正式开售日维护）；CSV更新时自动重新计算。数据载入后默认选中这份动态列表；可以直接使用原有机型勾选器增删，再点「＋ 保存当前选择」生成可长期保存的独立快照；动态列表自身不可编辑或删除，不会覆盖用户已保存的列表。若没有符合条件机型，回退到默认品牌全选。品牌切换遵循原有选择行为。
- **我的列表**：系统动态列表与自动里程碑均不可删；用户自建列表可保存、重命名、更新、删除，并可通过 JSON 导入／导出。
- **品牌色系**：小米、REDMI 橙色；华为、荣耀 红色；OPPO、一加 绿色；vivo、iQOO 蓝色；苹果 紫色。新增品牌优先检查 `BRAND_HUE`，未知品牌使用通用调色板。

### 销量追踪 PNG

| 场景 | 输出 |
| --- | --- |
| 桌面 | 16:9、2400×1350；线尾写机型名称 |
| 手机 | 4:5、1200×1500；线尾写序号，底部按最新值列机型；最多两列 12 项 |

手机网页与手机导出保持接近：网页列表可展示全部条目，导出列表有容量限制；导出图不显示数据标签。导出用不透明背景并跟随浅色／深色模式；无法标名的线用浅灰细线并注明数量。

文件名规范：`新机周销量-列表名或品牌-横轴-纵轴-桌面/手机.png`。例如 `新机周销量-华为-自然-总销量-桌面.png`；列表名中的非法文件名字符替换为 `_`。周期范围不写入文件名。

## 4. 市场份额模块

- 五种展示：双图组合、横向发散、规模比例堆叠图、坡度图、哑铃图。默认展示双图组合；哑铃图标签不附加子品牌说明。
- **规模比例堆叠**：独立堆叠图和双图组合的堆叠部分复用 `getStackMarketScale()` / `getOrderedStackItems()`。基准周大盘指数固定为 100，仅从对比周当前趋势文案（`state.w2Market`，默认由 CSV 提供）提取明确的增减方向和百分比；对比周指数 = 100 ± 变化百分数。未识别出有效方向或百分比、下降超过 100% 时按持平。两周总长度分别按各自指数除以两周最大指数缩放；各分段为本周总长度乘本品牌份额。品牌顺序统一按基准周份额降序，拆分子品牌后独立排序；不改变原始份额、不把规模指数当绝对销量。
- 默认从 `market-share.csv` 自动读取历史数据并跟随最新连续两周；手动选择较早的历史周时固定该周，选回最新一周可继续跟随未来更新。也可手动导入本地 CSV。修改份额时切换到浏览器保存的手动编辑模式；重新选择周次或点击“重载仓库 CSV”会恢复 CSV 数据，后者跳转到仓库最新周。其他按六大集团差额补足。
- CSV 表头严格推荐：`ISO 周,趋势,苹果,华为,小米,OPPO,一加,realme,vivo,iQOO,荣耀`（`vivo` 小写；解析时保留对历史 `VIVO` 的大小写兼容）。一行一周，如 `2026W45`。OPPO 列包含一加／realme，vivo 列包含 iQOO；拆分时主品牌 = 集团 − 子品牌，禁止重复加总。必须提供全字段，校验各项在 0–100%、子品牌不大于集团、六大集团合计不超过 100%。
- 仓库 CSV 读取失败时，显示错误并允许导入本地 CSV；可保留当前版本本地配置，不再内置 W44/W45 示例。两周数据完整且有效才允许导出。更新 CSV 后无需修改 HTML。主副标题、周标签与洞察的手动覆盖可保留；趋势描述不适用跨周覆盖。点击“恢复所选周 CSV 原始数据”可撤销自动字段的手动覆盖。
- 六套主题：柔雾丁香、**编辑部米白（模块2与3统一默认）**、极简纯白、雾蓝极简、日落珊瑚、莫兰迪绿野。已选择过主题的浏览器仍优先使用本地保存的选项。
- 网页输入区保持浅色卡片；海报有独立主题。SVG 绘制后按所选分辨率经 Canvas 导出 3:4 PNG；尺寸与共同规范见第 6 节。
- 顶部趋势双卡每次切换所选周次时，直接从对应 CSV 行的 `趋势` 列生成 `大盘趋势：<趋势>`，不受历史手动文案覆盖标记影响；当前周可临时手动修改，但下次切换周次会恢复 CSV 描述。趋势卡文字使用中性主文字色，避免无条件表示上涨。品牌份额变化以百分点（pp）表示，而不是份额相对涨跌幅。主副标题、洞察和底部水印文案可手动编辑，原有覆盖规则保持不变。
- 抖音右侧交互区／底部文案区是独立安全边界，默认右侧 13%、底部 10%；预览参考线不应进入导出图。PNG 导出面板位于 CSV 数据面板之后。

## 5. 榜单推算模块

### 历史销量 CSV

- `sales-estimates.csv` 为唯一正式历史明细，固定英文表头，一行一个榜单条目。`dataset_id` 由来源、榜单系列、周期类型、规范化周期组成（各部分保留中文等原始文字，用 `|` 连接，仅转义字段内部的 `%` 与 `|`），排名在榜单内唯一。开发阶段不支持早期整段 URL 编码的旧 ID，也不自动迁移；旧开发数据应重新导出。TOP 数不参与 ID；`top_n` 是可选标称规模，`actual_count` 为真实条目数。25 条可记 TOP25，也可在原榜 TOP30 时记实际 25 条；标称规模须为不小于实收数的正整数；未知规模留空，不补零。
- 标准 CSV 表头（顺序固定）：

```csv
dataset_id,source,series,period_type,period,period_start,period_end,top_n,actual_count,rank,model,brand_group,pixels,estimated_units,estimated_wan,fit_k,fit_mode,calibration_count,accepted_count,outlier_threshold,algorithm_version,saved_at
```

- `period_type` 支持 `weekly`（ISO 周）、`monthly`（自然月）、`custom`（起止日期）。同周期若存在来源相同但口径不同的榜单，应填写不同的 `series`。品牌系列沿用 `BrandUtils.classify()` 的合并口径，机型字段保留榜单原始名称；合并行不可拆分。
- `estimated_units` 为四舍五入后的整数台数，`estimated_wan` 为该整数换算的四位小数，`fit_k` 保留计算精度；`fit_mode`、标定组数、有效组数、异常阈值、算法版本、保存时间随结果归档。仅 `single`、`fit`、`robust` 且补全机型名称的有效估算可进入正式 CSV；单组及剔除异常组的结果仍须人工核验。
- **读取与导出校验**：标准 CSV 使用 UTF-8（导出含 BOM）；表头、列数、合法周期、ID、排名唯一性、实际条目数与组内元数据必须一致。台数须等于 `Math.round(fit_k * pixels)`，万台值须在数值上等于台数除以 10000。允许起止日期为 `YYYY/M/D` 或 ISO 日期，以及万台小数省略末尾零；读取后规范化为 `YYYY-MM-DD` 和四位小数。不能为了容忍表格软件格式变化而放松实际数值和周期校验。一条非法记录会阻止整份新历史载入，提示异常记录或榜单；不会静默丢弃行。
- 页面加载仓库 CSV，刷新按钮以时间戳和 `no-store` 请求重新读取；读取失败时须成功重试或确认导入完整历史文件后才能合并导出，不能将失败当作空数据库。已加载的记录在刷新失败时可继续显示，但不得视为最新仓库数据。合并导出会保留其他周期，遇同 ID 数据变化须用户确认整期替换（旧版由 Git 提交历史保留）。同一会话的多次合并保留在内存，刷新前请下载备份；点击“刷新仓库历史”时若有未提交记录，必须先确认替换当前会话数据；如仓库被其他设备更新，应重新加载最新历史并导入未提交文件，再合并导出。浏览器不写回仓库，由维护者提交下载的完整 `sales-estimates.csv`。
- 本期标准销量 CSV 与历史文件表头相同，可导入合并；原标定报告、机型派生分析和品牌分析 CSV 保留作人工参考，不作为历史明细导入。发布 ZIP 增加本期标准销量 CSV。历史列表只读，不恢复截图、标定组原始输入或未完成草稿；选择历史榜单即同步图文工作台，也可点击“使用所选历史榜单生成图文”直接跳转。工作台沿用存档销量、品牌系列、柱长、标定状态及组数，四类图卡、文案、派生 CSV 与 ZIP 均用所选数据；历史 ZIP 的标准销量 CSV 保留已载入、规范化后的存档字段和原保存时间，不重算或补造标定组。点击“切回当前标定榜单”或成功导入新榜单截图，恢复当前标定工作流。历史数据不进入上方截图编辑器，不需要也不能在历史模式补造标定组。
- 实现在 `sales-estimate-archive.js`，周期计算复用 `iso-sales-week.js`。不要在前端保存仓库写入 Token，不要把缺榜条目当作零销量或把周榜与月榜累加。

### 标定与出图

- **估算销量展示精度**：前台结果表、历史榜单、数据概览、四类 Canvas 图卡以及自动生成的分析文案（历史榜单使用独立 `historyDisplayWan()`，其他业务视图使用 `displayWan()` / `displaySale()`），以万台为单位保留一位小数。销量差值和品牌合计先用原始精度计算再格式化；拟合计算、排名、柱长比例、已知标定输入及所有 CSV 原有精度不变。样本占比、销量倍数按各自格式展示。
- **单一截图入口**：页面默认打开空白标定编辑器，不内嵌 Base64 截图、预设榜单或测试柱长，不提供原图预览区域。左侧“导入新榜单截图”支持 PNG／JPG／WebP 白底、蓝色水平柱条榜单；当前识别算法接受 2–100 条柱条（无需固定 TOP30／TOP40）。图像仅在浏览器临时解码和测量，完成后释放 Object URL，只保留柱长等测量数据，不保存或上传图片。导入新图时重置标定、选择及周期元数据；已归档榜单从历史 CSV 选择。
- **机型名称录入**：按识别榜单的原排名逐行填写；忽略末尾空行，保留中间空行的行号且不覆盖该行旧名称。提示行数不符、未填写、超范围、缺失名称及未知品牌；刷新双机 PK 选项。未知品牌不可强行归并，品牌图卡和整套 ZIP 须先补全可识别品牌名称。
- 由柱长像素确定相对比例；必须输入**同统计期、同口径**的销量才能推算绝对量。
- 支持单机已知销量及最多五机合计标定，接受累计销量差值表达式，如 `782.87-689.03`。多组标定不一致时提示异常，避免给出不可信的绝对量。
- 品牌系列统计按当前**入榜样本**合并：小米＋REDMI、OPPO＋一加＋realme、vivo＋iQOO；苹果、华为、荣耀独立。展示条目数、样本合计和主力机型，不是全市场份额。
- 四种图卡：TOP10、双机销量 PK、品牌上榜实力、榜首领先。支持六套主题、文案编辑、3:4／9:16 两种比例、PNG／CSV／ZIP；分辨率见第 6 节。
- **榜单标签**：主视觉文案编辑区在副标题之后、账号水印之前提供 `copyTagLabel`。历史默认采用周期与 TOP 规模的规范短名（实收不足时标示实际条数），新截图若文件名能识别周次则取去掉扩展名后的简短标签，否则使用“本期入榜样本”，未导入时为空。标签属于展示层，不修改 CSV 周期、ID、文件名或统计口径；切换数据源时恢复相应默认值，切换模板／主题／比例时保留手动内容，清空则隐藏标签，恢复默认文案按钮可重置。四类图卡的预览、PNG 和 ZIP 共用 `getPosterCopy()` / `posterFrame()`；长文字限制宽度，背景适应文字长度。
- 双机 PK 机型名优先单行，必要时去除品牌前缀再自适应字号；销量数字保留光学左对齐处理。
- 桌面端工作台左侧独立滚动，右侧预览保持可见；窄屏改成上下布局。
- 右侧与底部安全区独立调节；底部免责附注在安全线附近独立定位，避免额外空白。品牌图卡的“品牌合并”固定说明位于免责附注横线正上方，由 `drawPosterFooter()` 与 `posterFooterGeometry()` 独立定位，随底部安全区整体移动并限制在右侧安全边界内，不随主体缩放，也不受自定义免责文字清空影响；品牌主体布局须为该说明及页脚预留空间。

- **公众图卡默认文案**：四类基础图卡和14个研究专题采用独立的简明文案策略（副标题、榜单标签、图表内附注、底部说明）。研究原始 `note`、`detail`、技术状态与导出CSV不直接照搬到图卡；公众默认只保留来源、估算性质、样本边界和影响阅读结论的关键提示。详见 [公开图卡文案规范](PUBLIC_POSTER_COPY_GUIDE.md)。用户手动修改的文案不自动覆盖；预览和正式导出共用图卡默认文案。

### 机型主数据与统一序列身份

- `model-master.csv` 为模块3长期机型属性表，维护于仓库根目录，根路径 `/model-master.csv` 同时供公开模块4读取，`/studio/model-master.csv` 仍要求授权；V3.3 初始接入110行、20字段。机型按永久 ID 保持唯一，退出榜单不删除；首发价格为正式首发定价，不含首销限时优惠、补贴、平台券及后续降价；起售 RAM/ROM 与该价格对应，均以纯数值维护（元、GB），日期统一定义为中国大陆正式开售日期，不新增发布日期或预售日期字段。`data.csv` 和 `sales-long.csv` 的 `date` 与 `model-master.csv` 的 `sale_start_date` 采用相同口径。发布会、媒体沟通会、预约及开始预售均不等于正式开售；优先查证官方开售公告或明确记载正式首销的可信报道。若查不到正式开售日期，但能确认正式发布日期，则暂按发布即开售取发布日期，在主数据备注或核实资料中注明「正式开售日未查证，暂按发布日期」，后续取得证据再更正；不把该暂定日期描述为已核实的正式首销。发布日期也未知则留空待核实。
- 按标准名称或别名归一化精确匹配，保留人工芯片归类，来源备注不覆盖主字段；上一代 ID 可暂未收录，不影响加载。相关字段约定见 [模块3架构](MODULE3_ARCHITECTURE.md)。已接入研究时间序列和默认属性/代际分组：统一以永久 ID 关联，未匹配用独立 unmatched: 标识，不使用旧 model_key 或迁移旧研究配置。同榜单身份冲突阻止研究序列，不影响原始历史读取。主数据异常单独提示，失败时允许临时销量研究；已新增价格、芯片、产品定位、年龄结构及多属性交叉专题。

### 热销机型追踪与十四个研究专题

- 按来源和榜单系列独立构建连续 ISO 自然周；只使用 weekly 类型历史。机型标识经 NFKC、大小写、空白及指定不可见字符归一化；原始名称不被重写。母品牌由 `BrandUtils.classify()` 统一识别。
- 默认覆盖率 80%，分母从历史首次观测起、限制在所选区间；可改为完整区间自然周分母。覆盖率只计真实榜单观测，0% 仍须至少一次区间内观测。默认最多连续缺失 3 周，可调 0–12 周；原始观测模式或 0 周禁用插补。
- 默认内部线性插补，并在完整 TOP N 榜单中以末名销量为上限；只有排名 1–N 全部存在、声明条数一致才有有效门槛，实收不足不得伪造阈值。无门槛线性模式可选。整周缺榜的内部插补可关闭；仅当最新历史末周缺失、前一周有真实观测且完整末名门槛存在时，允许门槛约束末周估算。不得向首次观测前外推。未能填补的缺失仍为空；区间内首次观测后出现未填补缺失，后续累计量保持不可计算。插补不是实测销量。
- 产品销量研究：机型销量趋势、代际替代分析、产品结构分析、同档代际对比；分组和配对可由主数据生成，也可手动配置，机型趋势及同档配对可选择自然周或完整销售周同期；其余固定分组保持自然周。代际样本比例变化不证明用户实际换机。TOP30不保证完整系列机型覆盖，因此不提供独立的系列销量趋势专题；产品系列仅作为共享属性、分组及代际配对依据，相关统计仍为所选样本。
- **代际替代双轴图**：固定旧代、新代分组，按同一自然周统计；蓝柱为两代合计周增量（左轴，万台；按所选自然周内有效合计销量峰值预留5%空间后向上对齐可读刻度，无正销量时回退至1万台量程），紫线为新代周增量÷两代合计×100%（右轴，固定0–100%），50%及80%仅绘制参考虚线，不显示独立标签或逐点/柱顶数值。两代任一组缺失则该周合计和替代率均留空；合计为零时比例不可计算；含插补的柱降低透明度、相关折线段使用虚线，缺失不跨周连接。预览和PNG共用 `drawGenerationDualAxis()`，沿用图卡主题；网页研究预览的左右纵轴及横轴仍使用系统无衬线字体栈 `--ui-font-body`；海报及直接 PNG 的坐标轴改用公共 `researchPosterAxisText()`，周次和标题使用思源黑体字体栈，独立数字及百分比使用 IBM Plex Mono 字体栈；表格保留两代销量和占比并追加合计，图表CSV及发布清单分别记录万台与百分比。
- 榜单生态研究：长尾韧性分析、榜单流动分析、榜单品牌结构与集中度；跨模块研究：TOP30市场覆盖率与销量分层、榜内与全市场品牌竞争分析。上述专题在原始模式不使用覆盖率和插补条件；品牌结构与集中度亦支持扩展样本，其余四个固定原始口径。固定 TOP K 对榜单流动、榜单品牌结构生效；缺少任一前 K 名则该周不可比较。流向图连接同一品牌，并不表示用户换机流动。榜单 CR1/CR3/CR5 和 HHI 按销量份额计算。「品牌结构与集中度」的多周堆叠柱可按榜单销量占比、上榜数量占比或绝对销量绘制；相邻两周均有效时，在对应品牌柱形边界之间使用约19%透明度的相同品牌色带，贝塞尔曲线平滑连接，缺失周不跨越。此效果通过 `brandStack.connectAdjacentBrands` 开启，绘图发生在柱形和数值标签下层，双周及集中度等其他图表不受影响。
- **时间序列堆叠图统一绘制**：`research-charts.js` 的 `drawBrandComposition()` 负责常规 `brandStack` 多周堆叠图，`drawDualBrandFlowMulti()` 负责跨模块上下双面板布局；两者的相邻周色带均调用统一的 `drawAdjacentStackRibbons()`，按稳定类别标识连接对应色块，并统一使用约 19% 透明度及平滑贝塞尔曲线。研究数据构建仍各自独立，`sales-estimate-archive.js` 的 `attrTrend()` 对 `view==='stack'` 生成 `connectAdjacentBands:true`，覆盖价格带历史、芯片供应商／芯片平台历史、代际年龄结构历史堆叠；榜单品牌结构堆叠同样设置此标志。相邻自然周有缺失、任一周无有效样本或类别值不可计算则不跨周连接，且不改变份额分母、未知类别、分类顺序、颜色、百分比与销量计算。末周价格带×品牌、末周芯片×品牌等 `attrMatrix()` 非周序列堆叠不启用连接。预览Canvas与PNG研究图卡共用同一绘制函数。
- **榜内与全市场品牌竞争分析**：双周默认发散式堆叠贡献图，深蓝榜内贡献、浅蓝榜外贡献，菱形为全市场净变化，品牌名下标两周全市场份额，六品牌按净变化降序。令 S 为品牌榜内销量、M 为全市场可行规模、p 为原始全市场品牌份额（百分数），每周榜内分量为 100S/M，榜外分量为 p−100S/M；各分量双周差值为贡献（pp），二者之和严格等于 Δp。沿用SKU与六品牌残差约束的交集，以规模区间中点计算、端点推导贡献变化范围，区间包含零且不恒为零则方向不确定；范围见表和CSV，非统计置信区间。无可行区间则不画贡献柱，保留可用市场变化菱形，不补零。其他品牌不绘制、不重新归一化；多周堆叠不变。预览、PNG、图卡及ZIP使用同一数据快照。
- **覆盖率默认上下双图**：上图保留市场规模及原有情景带与趋势冲突标识；下图是同周原始排名1–3、4–10、11–30、榜外四层100%堆叠，榜外以浅紫色区分。各层以市场规模情景中点为分母，榜外为中点减TOP30；没有可行区间时该周分层留空，不以市场下界代替真实总量。其他覆盖率、环比指数、偏差视图保留。
- **TOP30市场覆盖率与销量分层（派生入榜率＋独立约束）**：仍固定原始排名1–30名，TOP40只取前30名，不插补；榜单任何一个名次缺失时不计算该周TOP30完整销量。记完整TOP30销量 T、榜内苹果销量 A、该周原始第30名估算销量 L（均单位万台）、模块2同周苹果市场份额 p（作为0—1的小数）。市场规模的基本锚点 A/p，考虑TOP30是全市场子集后必要下界 M_low=max(T,A/p)。若启用可独立开关的SKU约束，用户仅填写假设的榜外苹果机型数量上限 n（默认2款，范围0—20），该周市场总销量条件性上界 M_high=(A+n×L)/p；L 每周自动从原始 CSV rank=30读取，不存在固定3万台输入或默认。只有 M_high≥M_low 时形成SKU可行区间；否则标记「SKU假设上界低于必要市场下界」，不强制裁剪也不将其视为真实市场异常。紫色销量中心线仅在有可行SKU区间时绘制算术中点 (M_low+M_high)/2，浅紫带绘制 [M_low,M_high]；中点仅便于视觉比较而非数据驱动的统计点估计。关闭SKU约束时市场规模只能确定下界 M_low，紫线明确命名「市场总销量下界」，不生成误差带或中点。苹果入榜率从可行区间反推：最大入榜率 A/(p×M_low)，在有上界时最小入榜率 A/(p×M_high)，中点隐含值 A/(p×M_center)，统一输出百分数且不可编辑。TOP30覆盖率范围相应由 T/M_high—T/M_low 推导；缺SKU时仅有上界。第二个独立开关为模块2量化环比趋势检查（默认容差±5pp），只有前后相邻两个自然周均可计算且模块2有明确涨跌比例才比较。SKU区间存在时可行增长率范围为 [M_low,t/M_high,t−1−1, M_high,t/M_low,t−1−1]×100%；仅当模块2量化趋势（允许±容差）与整个区间不相交时标记「区间与量化趋势冲突」，连续3个相邻可比较周均冲突才标记连续异常。**中心增长率偏差超容差本身不标红**；SKU约束关闭时可报告基于两个下界的有条件环比参考差异，但没有市场规模上界，故不能判作真实市场异常，也不画红圈。没有量化趋势、间隔不连续或SKU区间无效时，检查显示证据不足并重置连续计数；趋势关闭时停止检查。旧版『苹果入榜率情景98,95,90,85』输入已移除，旧浏览器保存的值不再被作为独立输入；旧的覆盖率、环比指数与偏差三个视图保留但使用新的推导范围及参考口径。研究表格、图表CSV、发布清单及PNG/ZIP均记录两个开关、SKU数量、对应每周第30名销量、入榜率推导范围、市场边界和趋势状态。这里的上界依赖未入榜机型不超过该周第30名且SKU数量假设成立，浅色带为条件性情景范围而非统计置信区间或已核实的官方全市场销量。
- 机型追踪支持销量、原始排名、销量与排名双图及历史排名矩阵；原始排名来自同口径榜单，不重新排名、不插补，缺失不补零。双图共享时间轴并联动查看，排名轴按实际名次范围适配。四种视图均可进入工作台。全部14个研究专题统一提供独立「导出当前图表 PNG」入口，与「用当前专题生成图卡」并列；直接导出使用工作台当前主题、水印与导出宽度，按图种、周期、系列数量自适应画布，不使用固定海报比例或安全区裁切。直接 PNG 复用图卡内容绘制器，不截图；长尾纯表格视图导出完整统计表；数据无效时禁用，异步导出冻结当前数据及视觉参数。
- 工作台“返回来源”仅导航至对应历史榜单或专题，不重置发布快照或来源筛选；切换真实数据源另行处理。
- 研究专题可直接生成图卡、文案及专题 CSV／ZIP；海报标示来源、区间、样本、有效周及插补说明。发布时冻结当前内容与统计数据，不依赖之后的实时编辑。研究参数和分组、视觉设置按版本本地保存；发布方案显式保存／恢复，数据变更不复用旧统计文案。
- 历史 CSV 初始化先于研究初始化；研究错误单独报告，历史加载、刷新、导入与估算/工作台同步不应被研究 UI 阻断。参见 [模块3架构与派生数据](MODULE3_ARCHITECTURE.md)。

## 6. 统一图卡与水印规范（模块 2 / 3）

- 操作界面统一为浅灰／白底、浅色边框、蓝色交互强调，右侧安全区红色、底部安全区橙色。
- **单一主题来源**：`poster-themes.js` 是模块2（SVG）和模块3（Canvas）的六套海报主题唯一数据源。不要在页面内复制第二套主题字面量、固定背景或静态色卡。
- **共同层级**：主题渐变外底（`bgTop` → `bgBottom`）→ 白色圆角主卡片（`#fff`＋主题色边框）→ 白色图表／数据内卡（同主题边框）→ 低透明度主题色的重点行。两模块主卡留边、圆角、点阵密度统一读取 `PosterThemes.layout`。页面操作区仍使用独立的浅灰白卡片式 CSS，不随海报主题变化。
- **主题颜色语义**：`upColor` = 主强调色／份额上升；`downColor` = 辅助强调色／份额下降；`textPrimary`、`textSecondary`、`textMuted` 构成文字层级；`cardBorder`、`gridLine` 分别负责容器边框和中性数据底轨。模块3的榜首用主题主色、其他机型用辅助色，**不应把“排名落后”解读为负增长**。
- **极简纯白主题**：统一红涨绿跌；其它主题仍按各自语义色定义。
- **品牌识别色独立**：模块2份额堆叠使用各品牌固定识别色，不能为了套用主题而改掉苹果、华为、小米等品牌的标识颜色。模块3机型追踪采用母品牌色及12档机型深浅，叠加18种原生数据点标记；同一次选机的销量及排名使用相同形状，图例与导出同步，超过18款循环。形状按当前选机顺序分配，不承诺跨筛选永久不变；虚线表示含插补，空心不能单独用于判断插补。
- **维护纪律**：新增海报主题先改 `poster-themes.js` 的语义色；模块2／3色卡从该脚本读取主题色。涉及 SVG／Canvas 海报渲染、主题语义或导出代码的修改才做对应主题、比例和 PNG／ZIP 的针对性验收；仅修改操作台 CSS 不要求全面导出测试。
- **字体与字号**：模块 2／3 的网页操作台只保留 **4 档字号**：12px（辅助说明）、14px（正文、表格及输入控件）、16px（普通章节和面板标题）、24px（重点指标、大型分区标题及页面主标题）。旧 11px 并入 12px；旧 20px 根据用途归入 16px 或 24px。没有明确的信息层级差异，不得为了装饰或微调增加新字号，优先调整字重、颜色及间距。只在**独立纯数值字段**使用 IBM Plex Mono，包括数字输入、排行、销量与比例；中文标题、列名、选项、日期及数字与中文混排的说明（例如“3:4 竖屏比例”“15%（推荐）”）使用中文无衬线正文字体，不要因其中存在数字而给整个元素添加 `font-mono`。网页操作台的字号规范不覆盖 SVG／Canvas 海报内部独立字号与排版。字体从网络加载失败时回退系统字体；Canvas 单独数字做字形左边界修正。
- **共享操作台 CSS（单一来源）**：模块2、3均以 `<link rel="stylesheet" href="studio-ui.css">` 加载 `studio-ui.css`。它统一 4 个 `--ui-text-*` 字号变量、字体栈、颜色、间距和 `.ui-panel`／`.ui-section-title`／`.ui-field`／`.ui-palette-grid`／`.ui-palette-card`／`.ui-swatches`／`.ui-watermark-card` 等控件。添加相同功能的控件，先复用 `ui-*` 类，不在模块内部重新写同名色卡／水印 CSS；模块特有布局可保留在各自 HTML。
- **模块3移动端海报排版**：以3:4（360×480逻辑单位）为首选，9:16（360×640）为补充。`POSTER_DESIGN` 以360逻辑宽度定义字号及4单位间距尺度（4/8/12/16/24/32），通过 `posterDp()` 映射到原1080参考坐标，不改变四档PNG分辨率、安全区、水印及比例。主标题24、副标题14、正文及标签13、数值12、附注8、普通数据最小阅读目标12；低于目标提示，不保证所有密集专题均达标。公共标题区与页脚用 `posterBlock()` 测量字形升降部、按内容计算基线和行距；品牌榜按实际文字宽度选择并排/换行并按各行所需高度分配空间。普通趋势、机型追踪、代际双轴、榜单流动及市场销量分层使用10/400图例与15逻辑单位行高，按实际宽度流动排布，英文单词不拆分；常规纵轴12/400，按最长数字计算边距，采用友好刻度和至少4单位间距；横轴最多5个、按实测宽度继续疏化，上下双面板只显示底部周次；`RESEARCH_POSTER_AXIS` 标题39参考像素/500，刻度及周次36参考像素/400。独立数值与百分号、pp使用 IBM Plex Mono 字体栈（字体不可用时回退等宽字体），周次与数值刻度显式统一 IBM Plex Mono，中文分类刻度、品牌名、图例及中文说明使用正文黑体。`drawPosterRibbon()` 为单个双周 `brandRibbon` 海报及独立PNG预留实测品牌名和变化值列、按对比度选择色块数字前景色、密集标签避碰与引导标注，取消重复图例；极窄时使用色块列内白底标注，无法完整排布则阻止导出而非丢弃数字。独立双周图PNG增加高度，不强制3:4；网页研究预览不变。密集矩阵、多面板流向图、堆叠图及部分榜单局部布局仍需专项适配；不改变统计口径或数据。320/360/390/400px预览选项只改变CSS展示宽度。
- **模块3图内文字统一规范**：`POSTER_DESIGN.type` 统一常规机型、品牌与分类标签13，独立数值/排名/坐标刻度12，图例10，来源与附注8；常规正文500，坐标刻度、图例及辅助说明400。海报和独立研究PNG主体使用同一字重限制及混排字体，页眉与核心大数字保留层级，密集专题仍按实际单元和绘图区约束字号、保留可读性提示。图例10、附注8是明确例外，不降低普通标签12的审计门槛。TOP10排名列、机型列约从36、66起排（无安全区时），进度条跟随机型列。TOP10、销量PK、品牌榜、榜首模板的销量单位统一在页脚注明；研究图轴标题/百分比/pp等必要单位保留。销量PK参考和对比标题分别与各自进度条共享主题颜色。网页研究预览保留原有样式。
- **模块3折线及坐标轴**：`POSTER_DESIGN.chart` 普通线宽1.2、点半径1.7、描边0.8、网格0.5逻辑单位（高亮线宽1.8为预留设计值）。`posterValueAxis()` / `posterRankAxis()` 产生可读的数值和整数排名刻度，`posterAxisGutter()` 预留固定字号标签列宽，`posterYTicks()` 去除相互碰撞的刻度；`posterWeekTicks()` 最多5个周次并按实际文字宽度避碰，密集品牌增长子图至多3个，仅底排显示。`posterLineLegend()` 统一使用10/400正文黑体测量及绘制，按实测项目宽度排布，长项目占用独立行，按词换行，避免破坏英文词。应用于趋势、机型追踪、代际双轴、榜单流动、市场规模/销量分层及品牌增长折线；矩阵、非折线专题的局部坐标及布局仍有独立空间限制。网页预览不变，不删除数据点。
- **周次格式统一**：同年 ISO 自然周轴使用 `posterWeekLabel()` 输出 `WXX`，跨年保留完整 `YYYY-WXX`，非自然周类别不变。价格带、芯片平台、新老代际及品牌结构等共用 `drawBrandComposition()` 的时间堆叠图，海报与独立PNG统一接入 `posterWeekTicks()`（12/400、IBM Plex Mono、最多5个刻度）；原始柱子、色带和数据不变。双市场多周流向、品牌竞争热力图、排名矩阵也使用相同周次格式，但保留各自密集布局限制。
- **堆叠图纵轴**：`drawBrandComposition()` 的海报与独立PNG纵轴使用公共 `posterAxisGutter()`、`posterYTicks()`，固定12/400与 IBM Plex Mono，轴标题13/500，按实测刻度宽度预留左侧空间；柱内数值仍受色块局部空间约束。保留原有轴范围和堆叠比例，网页研究区预览样式不变。
- **底置图例间距**：`POSTER_DESIGN.chart.axisLegendGap=8`，X轴末行（有轴标题时为标题）文字下缘至底部图例文字/标记上缘至少预留8逻辑单位；`posterAxisLegendDistance()` 按实际文字升降部和图例标记高度计算基线距离。时间及分类堆叠图、普通及长尾散点图、双市场多周流向图在分配绘图区高度前预留该空间；底置多行堆叠图图例行高至少15。保留图例、刻度字号及全部数据；网页研究区原预览布局不变。

- **操作台字体统一（全控件）**：`studio-ui.css` 中 `--ui-font-body` 采用系统 UI 字体栈，模块2／3的标题、英文标识、按钮、表单、表格、说明、色卡和水印设置均使用它；首页顶部导航也引用该变量，但首页 ECharts 继续使用原有 `--f-body` 做文本测量和导出，不能改动。独立纯数值使用 `--ui-font-number`（IBM Plex Mono）。模块2加载的 Noto Sans SC 等网络字体仅用于有独立字体规则的 SVG/海报；模块3 Canvas 海报文字同样独立，不因操作台字体统一而改动。操作台 CSS 字重使用 400／500／600／700／800，避免 650／750／780／850 等额外字重。页面主标题统一为 24px、800 字重，较长标题允许窄屏换行。
- **维护边界**：`studio-ui.css` 管理模块 2／3 共用的操作台组件；`market-share.css` 管理模块 2 特有的控制台布局、数据编辑表格、开关和安全区模拟层。模块 2 已移除 Tailwind CDN 和工具类，不再新增 Tailwind 或复制一套原子工具类；优先为真实控件设置简明的语义 CSS 类。两份 CSS 均不覆盖海报 SVG、Canvas、`poster-themes.js` 或第三方 ECharts。模块3主题按钮在 `syncPaletteChooser()` 中切换 `is-selected`，模块2在 `renderPaletteButtons()` 中设置该类与 `aria-pressed`。
- **模块3按钮规格**：普通主次操作按钮 `.primary` / `.secondary`、模块页签 `.module-tab-button`、研究专题导航 `.research-topic-button` 共用基础几何与字体（12px、600字重、1.5行高、40px最小高度、9px 13px内边距、1px边框、9px圆角）。主次操作仅通过颜色区分；页签以 `aria-selected`、研究导航以 `aria-pressed` 表示选中，切换只改变颜色、不替换基础样式。保留禁用、悬停及键盘焦点反馈。专用模板卡片、图文导出控件及其他模块不受此规则影响。
- **界面简化原则**：以排列整齐、数据清楚、功能正常为目标；不为简单操作界面新增渐变、复杂阴影、动画或装饰性控件。图表预览的安全区模拟层仅作辅助显示，导出 PNG 使用独立 SVG 克隆与 Canvas 序列化，不依赖 Tailwind 样式。
- **人工验收**：修改共享样式或控件 HTML 后，手动检查两模块主题色卡、水印卡片在桌面／窄屏下的溢出与间距。

- **图片水印**：全屏倾斜（默认关闭，`归零return0`，透明度 8%，字号 32px，间距 220px）与中心单个（默认关闭，同文案，透明度 12%，字号 72px）互斥。模块 3 左上角账号默认同为 `归零return0`，与数据来源说明分离，不因账号名称修改而更换原始数据归属。水印覆盖图卡可用内容区域，预览及 PNG 一致；模块 3 的四图 ZIP 一样会带水印。
- 模块1桌面及手机 PNG 不再渲染底部网址水印；模块3对比卡的标签使用“参考机型／对比机型”，空角标水印不绘制，双空回收顶部72px。
- 水印设置保存在浏览器：模块2使用带版本号的页面状态，模块3使用版本化视觉配置。旧版配置不再迁移，版本不匹配时使用默认值；清空当前版自定义文案不应自动恢复默认文字。
- 安全区默认启用，右侧 13%（0–30%），底部 10%（0–25%），横纵独立规避而非整体缩放。参考线可独立控制，导出时不包含安全线或交互区遮挡模拟层。按钮单独导出当前布局；启用安全区后“多版本导出”生成同名后缀 `_规避版.png` 与 `_完整版.png`，后者关闭规避，保持同一快照的其他配置，串行渲染并提供分别下载入口。

### 出图比例与 PNG 分辨率

模块 2 固定 3:4，模块 3 支持 3:4 与 9:16；两者统一四档导出宽度。分辨率只改变最终像素数，不改变预览尺寸、图卡排版、主题和安全区比例。模块 3 单图和 ZIP 使用相同选择；极清档需要更多内存。

| 档位 | 3:4（模块 2 / 3） | 9:16（模块 3） |
| --- | --- | --- |
| 标准 | 1080×1440 | 1080×1920 |
| 高清 | 1620×2160 | 1620×2880 |
| 超清（默认） | 2160×2880 | 2160×3840 |
| 极清 | 3240×4320 | 3240×5760 |

模块 2 从 SVG 逻辑画布按目标尺寸栅格化；模块 3 从 1080 宽的逻辑画布按像素倍率直接渲染，避免对低分辨率预览截图放大；安全区参考线仅用于预览。模块 1 的桌面／手机输出仍遵循第 3 节，不使用以上四档。

### Cloudflare 分模块部署

- 原有根目录源码与 CSV 仍是维护源；Cloudflare 构建通过 `scripts/build-cloudflare.mjs` 的明确白名单生成 `dist/`。模块 1／2／4 的页面、数据及依赖按白名单公开；模块 3 及其独立历史和衍生 CSV 放在 `/studio/`，保留模块 2 的兼容副本供跨模块研究使用。不发布 README、维护文档、测试和 Git 历史。

### 10.1 长表协议（UTF-8 CSV）

```csv
brand,model,category,date,period,metric,value_wan,operator
华为,示例机型,旗舰SO,2026/10/1,2026-W44,cumulative,100,>=
华为,示例机型,旗舰SO,2026/10/1,2026-W45,weekly,8.6,=
```

上例为格式示意，不是项目销量。以品牌、机型、ISO自然周、metric 为唯一记录键；同一机型的 category/date 保持一致。date 沿用跟踪源表字段，机型属性研究及生命周期以主数据正式开售日为准。period 统一 YYYY-Www；metric 仅 cumulative（累计）/weekly（独立周增量）。value_wan 为非负数，单位万台；operator 为 =（精确）、<（严格上界）、>=（下界）、≈（近似，无默认误差范围）。同周可并存两种 metric；空白没有记录，0 是有效精确观测。不得按数值是否为50的倍数重新判定长表语义。
